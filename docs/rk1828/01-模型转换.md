# 01 · 模型转换（PC 端）

把 HuggingFace 模型导出为 ONNX，再用 RKNN3-Toolkit 转成 RK1828 可用的 `.rknn`。本文以 **Qwen3-0.6B** 为例，全程在 **x86_64 PC** 上完成，**不需要目标板**。

> 适用对象：RK3576 / RK3588 host + **RK1828** 协处理器。
> 协处理器只加速主网络计算与采样；tokenizer / chat-template 仍在 host CPU 上跑。

---

## 0. 前置条件

| 项 | 要求 / 本项目实际值 |
|---|---|
| 架构 | x86_64 Linux |
| Python | 3.12（搭配 cp312 toolkit wheel；官方文档写 3.10，搭配 cp310 wheel 亦可） |
| Full toolkit wheel | `rknn3-toolkit/rknn3-toolkit/packages/rknn3_toolkit-1.0.4-cp312-cp312-manylinux_2_17_x86_64.manylinux2014_x86_64.whl` |
| 网络 | 能访问 HuggingFace（本机经代理 `https_proxy=http://localhost:7897` 直连 hf.co） |
| GPU | 可选。`export_llm.py --quant`（AWQ+GRQ 权重量化）需要 CUDA；无 GPU 时该参数被跳过，`export_rknn.py` 的 GRQ 量化改走 CPU（0.6B 约 15–20 分钟） |

> ⚠️ **不要用 lite wheel 做转换**。`rknn3_toolkit_lite-*`（aarch64）是板上推理用的，PC 端转换必须用 **full toolkit**（`rknn3_toolkit-*-x86_64`）。

## 1b. GPU 机器上做转换/量化（推荐，量化快很多）

`export_llm.py --quant`（AWQ+GRQ 权重量化）**只在 `torch.cuda.is_available()` 为真时才跑，无 GPU 会整段跳过**（模型不做 GRQ 预量化）。在有 NVIDIA GPU 的机器上做转换，0.6B 量化几十秒即可（CPU 要 15–20 分钟），4B/7B 受益更大。要点：

```bash
# 1) 装匹配本机 CUDA 的 torch（如 CUDA 12.8 用 cu128；驱动够新即可，cu126 也能跑）
.venv/bin/python -m pip install torch==2.7.0 --index-url https://download.pytorch.org/whl/cu128
# 2) 其余依赖照常（requirements.txt 已含 datasets/optimum/peft/modelscope/accelerate）
.venv/bin/python -m pip install -i $PM -r requirements.txt
# 3) auto_gptq 单独装：避开 nvcc 编译（导出 GPTQ 不需要推理 kernel）
BUILD_CUDA_EXT=0 .venv/bin/python -m pip install --no-build-isolation auto_gptq==0.7.1
# 4) 装 toolkit wheel（--no-deps 防止把 torch 拽回默认 cu 版本）
.venv/bin/python -m pip install --no-deps "$WHEEL"
# 验证 GPU 可见
.venv/bin/python -c "import torch; print('cuda', torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

> 💡 **uv 免 sudo 搭建**：若机器没有 pip/`python3.12-venv`（Ubuntu 常见）且 sudo 要密码，可用 `uv`（`curl -LsSf https://astral.sh/uv/install.sh | sh`）：`uv venv --python 3.12 .venv` + `uv pip install --python .venv/bin/python ...`，命令同上。注意 uv 建的 venv 默认不带 pip，用 `uv pip freeze` 而非 `.venv/bin/pip`。

**GPU 转换三个非显然的坑：**

1. **`datasets` 必装**：GRQ 量化 `rknn.utils.grq` 要 `load_dataset`，缺它报 `ImportError: cannot import name load_dataset`。（已加入 requirements.txt。）另注意仓库根有个无 `__init__.py` 的 `datasets/`（CMMLU）目录，装上真 `datasets` 库后它会优先，不冲突。
2. **HF 不通时用 `--modelscope`**：部分服务器连不上 huggingface.co（代理也不行），convert.sh / export 脚本支持 `--modelscope` 从 modelscope.cn 下载（国内快）。
3. **大模型 export_rknn 会 OOM**：`register configuration`（codegen）阶段是内存峰值杀手，**4B/VL 在 31G RAM + 8G swap 下会被 OOM Killed**。解法：加大 swap（`sudo fallocate -l 48G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`，约 50G+ 即可）。被杀后用 **`convert.sh --skip-onnx`** 只重跑 export_rknn，复用已完成的 export_llm（不重跑下载+GRQ+ONNX）。VL 同理用 `--only llm` + `--skip-onnx`（若支持）或重跑整条。

> VL 多模态走独立 `.venv-vl`（transformers 4.57.1 / torch≥2.9），用 `--quant` 时同样要补上述 GPU 量化依赖，详见 `examples/Qwen3_VL/convert.sh` 头注释。

## 4. 导出 ONNX + 配置

```bash
cd /home/alex/project/violoop/rknn3-model-zoo
export PYTHONPATH=$(pwd)
cd examples/Qwen3/python
../../../.venv/bin/python export_llm.py \
    --model_path Qwen/Qwen3-0.6B \
    --export_llm_path ../model/llm/Qwen3-0.6B.onnx
```

产物（`examples/Qwen3/model/llm/`）：

| 文件 | 说明 |
|---|---|
| `Qwen3-0.6B.onnx` | 主网络（权重以外部文件分离存放，同目录大量 `onnx__MatMul_*`） |
| `Qwen3-0.6B.config.pkl` | chat_template / vocab_size / hidden_size 等配置 |
| `Qwen3-0.6B.tokenizer.gguf` | tokenizer（GGUF），**C++ demo 用** |
| `Qwen3-0.6B.embed.bin` | fp16 embedding 权重（vocab×hidden×2 字节） |

同时会在 `datasets/CMMLU/` 生成量化数据集 `dataset.txt` + `dataset_np/`。

> 若 `.tokenizer.gguf` 没生成，单独补：
> ```bash
> export PYTHONPATH=/home/alex/project/violoop/rknn3-model-zoo
> .venv/bin/python -c "from py_utils.export_llm_helper import export_tokenizer; \
> export_tokenizer('Qwen/Qwen3-0.6B','examples/Qwen3/model/llm/Qwen3-0.6B.tokenizer.gguf')"
> ```

## 5. 转 RKNN（关键：`--platform rk1828`）

```bash
cd /home/alex/project/violoop/rknn3-model-zoo/examples/Qwen3/python
../../../.venv/bin/python export_rknn.py \
    --platform rk1828 \
    --onnx_path ../model/llm/Qwen3-0.6B.onnx \
    --config   ../model/llm/Qwen3-0.6B.config.pkl \
    --rknn_path ../model/llm/Qwen3-0.6B.rknn
```

> ⚠️ `export_rknn.py` 默认 `--platform rk1820`，**RK1828 必须显式传 `--platform rk1828`**。
> 量化默认 `w4a16 / grq / group32`。无 CUDA 时走 CPU，0.6B 约 15–20 分钟。

产物：

| 文件 | 大小（0.6B 参考） | 部署用途 |
|---|---|---|
| `Qwen3-0.6B.rknn` | ~24 MB | 模型图 |
| `Qwen3-0.6B.weight` | ~387 MB | 权重（分离模式） |

加上第 4 步的 `.tokenizer.gguf`、`.embed.bin`，即为部署到板子的全部文件。

## 6. （可选）PC 模拟器验证

不用板子，在 PC 上用 toolkit 自带 x86 模拟器验证转换是否正确。脚本：`examples/Qwen3/python/test_pc.py`。

```bash
cd /home/alex/project/violoop/rknn3-model-zoo/examples/Qwen3/python
../../../.venv/bin/python test_pc.py --prompt "你好，请用一句话介绍你自己。" --max_new_tokens 64
```

要点：
- 模拟器推理**必须**经 `load_llm` + `build`（`load_rknn` 加载的模型不支持模拟器），所以脚本会**重新量化一次**（~15–20 分钟 CPU）。
- Qwen3-0.6B：`VOCAB_SIZE=151936`，`hidden=1024`，`SEQ_LEN=128`。
- 输出连贯中文即说明量化精度正常，可进入板端部署（见 `02` / `03`）。

## 附：升级到更大模型（1.7B / 4B / 8B）

- 第 4 步把 `--model_path` / `--export_llm_path` 改成对应模型名即可（如 `Qwen/Qwen3-1.7B`）。
- `VOCAB_SIZE` 仍是 151936；`hidden`/层数不同，脚本里 `embed.bin` reshape 用 `-1` 自动推断，无需改。
- RK1828 内存较大，VLM 类可加 `--no_prune_mode` 用完整模型（纯 LLM 不涉及）。
