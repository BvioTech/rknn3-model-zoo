# 03 · 部署到目标设备并运行

把 `01` 转好的模型文件传到板子，跑通 RK1828 上的 LLM 推理。前置：已完成 `02-目标设备环境修复`（运行库软链、协处理器已 start、Python 依赖就绪）。

> 目标板：dev14 = `192.168.1.70`（用户 `linaro`）。工作目录约定 `~/qwen3_test/`。

## 1. 传输模型与 tokenizer（PC → 板）

在 **PC** 上执行：

```bash
cd /home/alex/project/violoop/rknn3-model-zoo/examples/Qwen3/model/llm

# 模型三件套（rknn / weight / embed）
scp Qwen3-0.6B.rknn Qwen3-0.6B.weight Qwen3-0.6B.embed.bin dev14:~/qwen3_test/model/

# tokenizer（lite 用 transformers.AutoTokenizer，需要 HF tokenizer 目录，从本地缓存拷）
SNAP=$(ls -d /home/alex/.cache/huggingface/hub/models--Qwen--Qwen3-0.6B/snapshots/*/ | head -1)
scp "$SNAP"*.json "$SNAP"*.txt dev14:~/qwen3_test/tokenizer/

# 板端推理脚本
scp /home/alex/project/violoop/rknn3-model-zoo/examples/Qwen3/python/test_board.py dev14:~/qwen3_test/
```

板上目录结构应为：

```
~/qwen3_test/
├── .venv/                       # 02 建好的 venv
├── test_board.py
├── model/
│   ├── Qwen3-0.6B.rknn
│   ├── Qwen3-0.6B.weight
│   └── Qwen3-0.6B.embed.bin
└── tokenizer/                   # config.json / tokenizer.json / merges.txt / vocab.json / *_config.json
```

> tokenizer 只需 JSON/txt 配置文件，**不需要** safetensors 权重。

## 2. 运行推理（lite Python 路线，推荐）

在 **板** 上执行：

```bash
ssh dev14
cd ~/qwen3_test && . .venv/bin/activate

python test_board.py --target rk1828 --max_new_tokens 96 --prompt "你是谁？"
```

`test_board.py` 关键参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--target` | `rk1828` | 协处理器型号 |
| `--rknn_path` | `model/Qwen3-0.6B.rknn` | 模型图 |
| `--weight_path` | `model/Qwen3-0.6B.weight` | 权重 |
| `--embed_path` | `model/Qwen3-0.6B.embed.bin` | embedding |
| `--tokenizer_path` | `tokenizer` | HF tokenizer 目录 |
| `--max_new_tokens` | 512 | 最大生成长度 |
| `--prompt` | 内置两条 | 可传多条：`--prompt "问题1" "问题2"` |

## 3. 备选：板上预编译的 C++ demo

板上 `/usr/local/bin/rknn3_llm_demo` 是已编译好的同款 demo（无需自己交叉编译）。它吃 `.tokenizer.gguf`（不是 HF 目录）。

```bash
# 先把 PC 上的 tokenizer.gguf 传过去
# (PC) scp examples/Qwen3/model/llm/Qwen3-0.6B.tokenizer.gguf dev14:~/qwen3_test/model/

# 参数签名: <model.rknn> <weight> <tokenizer.gguf> <embed.bin> <core_mask hex> <prompt>
LD_LIBRARY_PATH=/usr/local/lib rknn3_llm_demo \
    ~/qwen3_test/model/Qwen3-0.6B.rknn \
    ~/qwen3_test/model/Qwen3-0.6B.weight \
    ~/qwen3_test/model/Qwen3-0.6B.tokenizer.gguf \
    ~/qwen3_test/model/Qwen3-0.6B.embed.bin \
    0xff "你是谁？"
```

### 自己编译（RK1828 板上本机编译）

上游 V1.0.4 起 `3rdparty/rknpu3/` 已随仓库提供 `include/rknn3_api.h`、`include/float16.h`
和 `Linux/aarch64/librknn3_api*.so`（早期版本这里只有一个 README 占位，需自行拷贝，现已不必）。
运行库版本必须与板端一致：`librknn3_api` / `rknn3_transfer_proxy` / 固件三者相等。

板子本身是 aarch64，可直接本机编译，无需交叉编译器：

```bash
cmake ../examples/gemma4/cpp -DTARGET_SOC=rk3576 -DCMAKE_SYSTEM_NAME=Linux \
      -DTARGET_LIB_ARCH=aarch64 -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_EXE_LINKER_FLAGS="-no-pie" -DCMAKE_POSITION_INDEPENDENT_CODE=OFF
```

`-no-pie` 是必需的：`3rdparty/fftw` 的预编译静态库不是 PIC，而 Debian 12 默认 PIE 链接。

> 若确实要在 PC 上交叉编译，docker 镜像 `builder:violoop-pro`（ARM GNU 12.3 + sysroot）可用。

## 4. 重启后恢复

板子重启会丢失协处理器状态（驱动卸载、固件清空）。重新跑推理前先：

```bash
sudo /bin/rknn3_startup start          # 重新加载驱动 + 上传固件 + 起代理
# 若做了 systemd 自启（见 02 文末），则无需手动
```

各类软链（运行库、驱动、工具）持久化在磁盘，无需重建。

## 5. 排障速查

| 现象 | 处理 |
|---|---|
| `No RKNN3 library found` | 见 `02` 第 1 步：`/usr/lib/librknn3_api.so` 软链 |
| `rknn3_find_devices fail` / `DEVICE_UNAVAILABLE` | 协处理器未启动：`sudo /bin/rknn3_startup start`，验证 `ls /dev/pcie-rkep-*` |
| Load model failed | 检查 `.rknn` 与 `.weight` 是否配套、路径是否对 |
| Tokenizer 报错 | `--tokenizer_path` 指向正确的 HF tokenizer 目录（含 tokenizer.json 等） |
| embed 回调失败 / 乱码 | 确认 `embed.bin` 的 `VOCAB_SIZE`（151936）与嵌入维度一致 |
| 想换更大模型 | 按 `01` 重新转换 1.7B/4B，替换 `~/qwen3_test/model/` 下文件即可 |
