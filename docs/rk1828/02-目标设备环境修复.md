# 02 · 目标设备依赖 / 环境修复（板端）

把目标板从「开机但协处理器没起来」修到「RK1828 可被运行库发现、Python 推理环境就绪」。本文是 `03-部署与运行` 的前置。

> 目标板：**dev14 = `192.168.1.70`，用户 `linaro`（有免密 sudo）**
> 实测硬件：**RK3576（KICKPI K7）+ RK1828 PCIe 协处理器**（PCI `[1d87:182a]`，class = Processing accelerators）。
> 注意：是 RK3576，不是 RK3588；但同样配 RK1828 协处理器，转换时用的 `rk1828` 目标通用。

---

## 0. 先验证现象

```bash
ssh dev14
# 板子型号
cat /proc/device-tree/model            # Rockchip RK3576 KICKPI K7 Board
# 协处理器是否在 PCIe 上
lspci | grep -i accelerat              # 01:00.0 ... Rockchip Device 182a  ← RK1828
# 是否已有设备节点（修复前没有）
ls /dev/pcie-rkep-* 2>&1               # No such file ← 说明协处理器未启动
```

板上工具/已编译 demo 都在 `/usr/local/bin/`（`rknn3_startup`、`rknn3_llm_demo`、`rknn-smi`、`pcie_upgrade_tool` 等）。

## 1. 运行库路径修复（lite 只在 /usr/lib 找库）

`rknn3lite` 写死在 `/usr/lib/` 找运行库（`rknn3lite/api/rknn3_types.py:30`）：

```python
LIBRKNN3RT_PATHS = ['/usr/lib/librknn3_api.so',
                    '/usr/lib/librknn3_api_rkcp.so',
                    '/usr/lib/librknn3_api_native.so']
```

而板上的库在 `/usr/local/lib/`。建软链：

```bash
sudo ln -sf /usr/local/lib/librknn3_api.so /usr/lib/librknn3_api.so
ls -la /usr/lib/librknn3_api.so      # 确认软链生效
```

> 现象对照：修复前报 `No RKNN3 library found`；修复后改报 `rknn3_find_devices fail`（进入下一步要解决的协处理器启动问题）。

---

## 2. 启动 RK1828 协处理器（驱动 + 固件 + 代理）

协处理器 PCIe 枚举到了但没驱动绑定、没设备节点。需要 `rknn3_startup` 来：加载驱动 `pcie-rkep.ko` → 创建 `/dev/pcie-rkep-*` → 上传固件 `rknn3_rk1820.img` → 起 `rknn3_transfer_proxy` 守护进程。

但 `rknn3_startup` 脚本里多处路径写死、与实际不符，需先补软链：

```bash
# (a) 驱动：脚本找 /usr/lib/modules/pcie-rkep.ko，实际在带版本号的子目录
sudo ln -sf /usr/lib/modules/6.1.75/extra/pcie-rkep.ko /usr/lib/modules/pcie-rkep.ko

# (b) 工具：脚本调 /bin/xxx，实际在 /usr/local/bin
sudo ln -sf /usr/local/bin/pcie_upgrade_tool     /bin/pcie_upgrade_tool
sudo ln -sf /usr/local/bin/rknn3_transfer_proxy  /bin/rknn3_transfer_proxy
sudo ln -sf /usr/local/bin/rknn3_startup         /bin/rknn3_startup

# 启动协处理器（加载驱动 + 上传固件 + 起代理）
sudo /bin/rknn3_startup start
```

成功时 `start` 会打印固件下载过程，结尾 `Downloading firmware OK`。

### 验证

```bash
lsmod | grep rkep                    # pcie_rkep  ...
ls -la /dev/pcie-rkep-*              # /dev/pcie-rkep-0000:01:00.0
pgrep -af transfer_proxy             # /bin/rknn3_transfer_proxy 在跑
```

> ⚠️ **板子每次重启后协处理器会回到未启动状态**，需重跑 `sudo /bin/rknn3_startup start`（软链已持久化在磁盘，无需重建）。要免手动，见文末「开机自启」。

## 3. Python 推理环境（lite，无需 torch）

板上 Python **3.11.2**，原本没有 pip / ensurepip，且有 PEP668 `EXTERNALLY-MANAGED` 标记，需先用 apt 装 venv/pip。

```bash
# 装 venv/pip（有免密 sudo + 有网）
sudo apt-get update -qq
sudo apt-get install -y python3-venv python3-pip

# 建工作目录与 venv
mkdir -p ~/qwen3_test/model ~/qwen3_test/tokenizer
python3 -m venv ~/qwen3_test/.venv
~/qwen3_test/.venv/bin/python -m pip --version    # pip 23.0.1 ...

# 装依赖：numpy + transformers + cp311 lite wheel（不需要 torch！）
# lite wheel 先从 PC scp 过来，或放到 ~/qwen3_test/
cd ~/qwen3_test && . .venv/bin/activate
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
    numpy 'transformers==4.51.3' \
    ./rknn3_toolkit_lite-1.0.4-cp311-cp311-linux_aarch64.whl

# 验证
python -c "import numpy,transformers; from rknn3lite.api import RKNN3Lite; \
print('numpy',numpy.__version__,'tf',transformers.__version__,'rknn3lite OK')"
# 'None of PyTorch...' 警告可忽略（tokenizer 不需要 torch）
```

> lite wheel 选 **cp311**（匹配板上 Python 3.11）。位置：
> `rknn3-toolkit/rknn3-toolkit-lite/packages/rknn3_toolkit_lite-1.0.4-cp311-cp311-linux_aarch64.whl`

## 附：协处理器开机自启（可选，免每次手动 start）

把启动做成 systemd 服务：

```bash
sudo tee /etc/systemd/system/rknn3-coproc.service >/dev/null <<'EOF'
[Unit]
Description=RKNN3 RK1828 coprocessor startup
After=network.target

[Service]
Type=oneshot
ExecStart=/bin/rknn3_startup start
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now rknn3-coproc.service
sudo systemctl status rknn3-coproc.service
```

> 前提：第 1、2 步的所有软链已建好（持久化在磁盘）。

## 附：常见错误对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `No RKNN3 library found` | lite 在 /usr/lib 找不到运行库 | 第 1 步软链 |
| `rknn3_find_devices fail` / `RKNN3_ERR_DEVICE_UNAVAILABLE` | 协处理器未启动（无驱动/固件） | 第 2 步 `rknn3_startup start` |
| `/bin/pcie_upgrade_tool: not found` | startup 脚本路径写死 | 第 2 步 (b) 工具软链 |
| `failed to get pcie-rkep.ko` | startup 找不到驱动 | 第 2 步 (a) 驱动软链 |
